A static blog can stay simple and still feel considered.The note markup is intentionally plain: a label, a hidden checkbox, and a span. CSS handles desktop margin placement and mobile toggling. The useful work happens in the HTML document itself, where writing, links, headings, and notes remain visible without a build pipeline.

The background is cooler than stock Tufte CSS, moving away from the familiar yellow paper tone while keeping the low-contrast reading surface. The result is still bookish, but less sepia.

Scroll-driven note animation is progressive. If the browser supports `animation-timeline: view()`, margin notes gently enter as they pass through the viewport. The animation is also plain CSS. Unsupported browsers ignore it and keep the notes readable in their normal static position.

Markup Shape

The page does not need a custom component model to keep repeated ideas understandable. The sidenote pattern is short enough to paste where the note belongs, and that keeps the source close to the article.

<p>
  Text with a sidenote
  <label for="sn-demo" class="sidenote-number"></label>
  <input id="sn-demo" class="margin-toggle" type="checkbox">
  <span class="sidenote">The note text.</span>
</p>

For margin notes without numbering, use the same checkbox and span, but swap in a symbol label and the marginnote class. On wide screens the symbol hides and the note simply sits in the margin.

Why This Stays Small

Most personal blogs do not need data fetching, hydration, or a templating layer on day one.The tradeoff is that shared navigation is copied between pages. For a two-page site, that is simpler than introducing a build tool. Plain files are easy to inspect, move, publish, and repair.

Simple code is not automatically better, but code that can be read in one sitting has a real maintenance advantage.

The next post can be created by copying this file, changing the title and date, and adding a link on the home page. That is enough structure for a small static notebook.

Enough Page To Scroll

The animation only becomes visible when the page has real scroll distance. A note that starts in the first viewport may already be at the end of its view timeline by the time the reader notices it.

This extra section exists to make the demo honest. It gives the browser room to move each note through the viewport, which gives animation-timeline: view() a changing progress value to work with.

As you scroll, this lower sidenote should fade and slide into place.This is the first lower test note. It should be easier to see than the first note because it begins below the initial viewport. The effect is intentionally small enough to stay quiet, but now it should be visible instead of theoretical.

The rest of this section is ordinary writing. That is the point: the animation should decorate the reading experience without changing the structure of the document or requiring JavaScript.

Previewing Locally

Opening the file directly still works, but some browsers print noisy file:// warnings in the console. A local server avoids that without changing how the site is built.

python3 -m http.server 8080

Then open http://localhost:8080/. That keeps the site build-free while giving the browser a normal origin for links and assets.

The local server is only for previewing. The files are still static and can be published as-is. This note is another lower-page animation target. It should enter later than the first few notes and make the scroll-driven behavior easier to confirm.

One More Pass

There is still no dependency graph here. The home page links to this post, this post links back home, and the stylesheet is the only shared asset.

A blog can grow from this shape slowly. When there are five posts, copying the header is still acceptable. When there are fifty, that is the moment to introduce a generator or a tiny include step.

The important part is that the first version stays understandable. The markup for the notes is visible in the article, the CSS owns the layout, and the browser does the animation when it knows how.This final note should animate near the bottom of the article. It is a practical check that the demo still works after a full-page scroll.
